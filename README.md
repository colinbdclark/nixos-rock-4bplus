# nixos-rock-4bplus

NixOS board support for the Radxa ROCK 4B+. This repository includes configuration for the Rockchip RK3399 kernel and device tree, the AW-NB197SM wireless firmware, U-Boot provisioning and an eMMC layout.

This repository includes code generated by DeepSeek V4.1 Flash.

## Use

```nix
inputs.rock-4bplus.url = "github:colinbdclark/nixos-rock-4bplus";
inputs.rock-4bplus.inputs.nixpkgs.follows = "nixpkgs";
```

```nix
{
  imports = [
    inputs.rock-4bplus.nixosModules.radxa-rock-pi-4b-plus
    inputs.rock-4bplus.nixosModules.radxa-rock-pi-4b-plus-disk
  ];
}
```

| Export | Purpose |
| --- | --- |
| `nixosModules.radxa-rock-pi-4b-plus` | SoC and board support |
| `nixosModules.radxa-rock-pi-4b-plus-disk` | eMMC layout for installation, optional (import the board module with it) |
| `nixosModules.sd-image` | SD card image, with the U-Boot package defaulted from `hardware.rockchip.platformFirmware` |

The modules receive a `board` argument holding the U-Boot package, the firmware offset and the root partition start. The input does not read the consumer's `inputs` by name.

Option names follow the conventions of nixos-hardware. The SoC layer can be
replaced by that project's module later without renaming anything.

## Options

### Board

`modules/radxa/rock-pi-4b-plus/default.nix` declares no options. It sets:

- `hardware.rockchip.rk3399.enable`
- `hardware.rockchip.platformFirmware`, from the pinned Rockchip input
- `hardware.deviceTree.filter` and `hardware.deviceTree.name` for
  `rk3399-rock-pi-4b-plus.dtb`
- `hardware.firmware` for the AW-NB197SM NVRAM and Bluetooth firmware, and for
  the Raspberry Pi wireless firmware package that supplies the generic brcmfmac
  files
- `boot.supportedFilesystems.zfs = false`, because the Rockchip kernel provides
  no ZFS module

Values a consumer may replace use `lib.mkDefault`.

### SoC

`modules/rockchip/rk3399/default.nix`

| Option | Type | Default | Meaning |
| --- | --- | --- | --- |
| `hardware.rockchip.rk3399.enable` | bool | `false` | SoC support |
| `hardware.rockchip.rk3399.kernelPackages` | kernel set | the pinned Rockchip kernel | Kernel and modules |

The kernel comes from the Rockchip input rather than the consumer's nixpkgs.

### Family

`modules/rockchip/default.nix`

| Option | Type | Default | Meaning |
| --- | --- | --- | --- |
| `hardware.rockchip.enable` | bool | `false` | Rockchip family support |
| `hardware.rockchip.platformFirmware` | package or null | `null` | U-Boot package |
| `hardware.rockchip.firmwareOffset` | int, bytes | `32768` | Offset for the raw U-Boot write |
| `hardware.rockchip.rootStart` | string | `"16M"` | Start of the first partition |

`firmwareOffset` and `rootStart` are the single source of truth for the disko layout and the installer. The 16 MiB start leaves room for U-Boot in front of the first partition.

## Helpers

### `lib.provision`

Builds the installer application that runs `disko-install` on a board booted
from an SD image.

```nix
board.lib.provision {
  inherit pkgs;
  flake = self.outPath;   # the consuming flake's source
  config = "rock";        # configuration name to install
  extraFiles = [ ];       # files copied to the target; empty by default
}
```

`uboot`, `firmwareOffset` and `rootStart` default to the values in this flake, so
the consumer does not repeat them. Each `extraFiles` entry is copied to the same
path on the target; entries that are missing or empty are reported and skipped.

The consumer passes its own flake path. The helper never uses its own `self`:
inside this flake that path is the board support source, and an installer built
from it would install the wrong configuration.

### `lib.provisionPayload`

```nix
board.lib.provisionPayload {
  inherit pkgs;
  flake = self;           # the consuming flake, for collecting its inputs
  config = "rock";        # configuration name
  toplevel = ...;         # the system to install
  provisioner = ...;      # the installer from lib.provision
}
```

Returns a linkFarm named `provision-payload-<config>` holding the system, the
flake's inputs and the installer. `just provision-emmc` copies it to a board
before installing.

`flake` here is the flake itself, because the helper collects its inputs.
`lib.provision` takes the flake's store path instead, because it embeds that path
in the installer.

### `lib.flakeInputPaths`

```nix
board.lib.flakeInputPaths self
```

Returns the store paths of a flake and its inputs, recursively and deduplicated.
The consuming flake copies the result to a board, so the board can evaluate the
configuration without fetching the flake's inputs.

### `lib.substituters`

```nix
board.lib.substituters
```

Holds `extra-substituters` and `extra-trusted-public-keys` for the Rockchip
binary cache. A consumer applies it to the boards' `nix.settings`. Its own
`nixConfig` repeats the values, because Nix does not apply the `nixConfig` of a
flake input.

## What this flake does not do

- It does not set `nixpkgs.config.allowUnfree`, `hardware.enableAllFirmware` or
  `hardware.enableAllHardware`. The board module enables the firmware the board
  needs; broader policy belongs to the consumer.
- It does not declare hostnames, users, SSH keys, wireless networks, route
  metrics, firewall rules or power management.
- It does not rebuild firmware from source. Files under `vendor/` come from
  upstream releases; each directory records its origin, licence and commit.

## Checks

```console
nix flake check --no-build --all-systems   # formatting, script tests, evaluation
nix build .#checks.aarch64-linux.build     # the example system; needs a builder
```

`checks.<system>.scripts` lints the provisioning script with shellcheck and runs
its tests. `checks.aarch64-linux.build` builds the example configuration, which
imports both board modules and the disk layout.
